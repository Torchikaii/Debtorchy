# Phase 4: First-boot provisioning + build-time credential baking — implementation decisions

Plan: `.opencode/plans/phase-4-plan.md`. Executed 2026-08-01.

## Summary

Tasks 1-7 implemented and validated. Task 8 (VM E2E) is explicitly manual
per the plan and was handed off to the user. This document records decisions
made against the plan and deviations taken during implementation.

---

## Decisions confirmed as planned

- **No preseed template.** `iso/preseed.cfg` stays the tracked source of
  truth; `build-iso.sh` stages a temporary copy, so the tracked tree is never
  modified. Verified: `git status` clean of build artifacts after every build.
- **First boot as root** via a systemd `oneshot` service
  (`os-provision/firstboot/`). No NOPASSWD, no sudoers churn. `pc` keeps
  normal password sudo. `systemd-analyze verify` passes on the unit.
- **Minimal offline package set:** deselect-everything base + `sudo` +
  `cifs-utils`, installed in late_command with `--no-install-recommends`.
  Offline apt simulation against the built ISO resolves all 57 packages from
  the ISO pool; the `keyutils` package (only a Recommends of cifs-utils) is
  correctly NOT pulled. (`libkeyutils1` is a hard Depends of the krb5 stack
  and is expected.)
- **NAS creds placeholder** `@@NAS_CREDS@@` is its own `\`-continued physical
  line in the preseed late_command; empty input removes the whole line, so no
  dangling continuation is left behind.
- **deb822 apt sources** written for the installed system
  (`/etc/apt/sources.list.d/*.sources`) pointing at deb.debian.org and
  security.debian.org, replacing the stale cdrom source — internet fallback
  for provisioning.
- **mount.sh non-TTY guard:** `setup_credentials` skips prompting when
  `[ ! -t 0 ]`, logs a warning, and leaves `NAS_MOUNTED=false` instead of
  writing a bogus creds file. Verified with `mount.sh < /dev/null`.
- **local-repo.sh tolerant update:** `apt-get update -qq || log "..."`
  tolerates partial source failure (NAS-only machines with no internet).
- **Build-time prompts** fall back to defaults (`admin`) on empty/EOF input;
  NAS creds baked only when both username and password are given. Password
  values and the NAS username/password are single-quote shell-escaped
  (`'` → `'\''`) for embedding in the one-line busybox-sh late_command.
  Verified: a password containing `'` and a NAS password containing a space
  render to a valid `printf` command.

## Deviations from the plan

### 1. `md5sum.txt` must exclude the `isolinux/` directory

The plan's find command (`find . -type f ! -name md5sum.txt`) produced a
built ISO where `md5sum -c` FAILED on exactly two files:

- `./isolinux/isolinux.bin` — patched by xorriso's `-boot-info-table`
- `./isolinux/boot.cat` — regenerated by xorriso at build time

These cannot be pre-hashed because their on-ISO content is produced during
the build. The committed Debian `md5sum.txt` already excludes the entire
`isolinux/` directory for this reason. Adopted the same convention:

```bash
find . -type f ! -name md5sum.txt -not -path './isolinux/*' -print0 | sort -z | xargs -0 md5sum > "$TMP_ISO.md5sum.txt"
```

Result: `md5sum -c md5sum.txt` passes on the built ISO.

### 2. `gzip -k` instead of `gzip -f`

The plan's literal snippet `gzip -9 -f Packages` deletes the uncompressed
`Packages`, which contradicts the plan's own requirement that the regenerated
top-level `Release` list both `Packages` and `Packages.gz` (matching the
committed Release). Used `gzip -k -9 -f` to keep both.

### 3. Temp-copy staging placement

The old `build-iso.sh` copied `os-provision/` and `package-manager/` directly
into `iso/` and cleaned up on EXIT. Replaced with a `mktemp -d` stage that
holds `iso/` + `os-provision/` + `package-manager/`; `cp -a` preserves the
`debian -> .` circular symlink without traversing it, and the trap removes the
whole stage. xorriso points at the stage instead of `iso/`.

### 4. Static analysis — pre-existing warnings left untouched

shellcheck reports only pre-existing issues (mount.sh SC2046 quoting on the
`uid=$(id -u)` mount options, local-repo.sh SC1091 source-not-followed and
SC2034 unused `url`). No new warnings from this phase; fixing them was out of
scope per the phase-4 review-fix note to avoid scope creep.

### 5. Task 8 handed off (no code change)

8a/8b are manual VM tests (full unattended install + full provisioning). Per
user decision, the commands and verification checklists were provided to the
user instead of being driven here. No CI harness exists for them yet.

  on the service unit.

- Built ISO extracted: `md5sum -c` passes; no `@@` tokens; firstboot unit +
  scripts present; `start-vm.sh` carries the updated SSH hint.

  user/password incl. `'` and space) — renders valid shell, no `@@` left.

  closure; `keyutils` package not pulled under `--no-install-recommends`.
